HeapView 零拷贝方案探测

用 GCHandle.Alloc(array, Pinned) 把 .NET 数组钉在 WASM 线性内存上， 再把内存地址 + 长度交给 JS，由 JS 用 new Uint8Array(wasmMemory.buffer, ptr, len) 建出指向同一块内存的 TypedArray。

关键是 buffer 从哪来，本模块换过两版，三条路现在并列在页面上： ①-a 扫全局（wasmMemory / HEAPU8，已被 ⑨ 证伪）； ①-b 公开 API runtime.localHeapViewU8().buffer（现在的正解）； ①-c 前一版的引子绕道 _unsafe_create_view()（降为对照，两者是同一块内存）。 此后逐一验证： ② pin 到的地址是否落在 buffer 内（不只是非零）、 ③ As() 的视图写入会不会回写到 C# 数组（零拷贝是否成立）、④ To() 副本的隔离性、 ⑤ 跨一次同步调用是否仍有效、⑥ 4 字节视图的对齐与宽度校验、 ⑦ 用 Module._malloc 把堆撑大，看视图会不会随 buffer detach 而静默失效（本方案的硬伤）、 ⑧ 那块 buffer 是不是整块线性内存（跨数组验证）。进入本页会自动开始运行。
