HeapView 零拷贝方案探测

用 GCHandle.Alloc(array, Pinned) 把 .NET 数组钉在 WASM 线性内存上， 再把内存地址 + 长度交给 JS，由 JS 用 new Uint8Array(wasmMemory.buffer, ptr, len) 建出指向同一块内存的 TypedArray。

关键是 buffer 从哪来：①-a 扫全局（wasmMemory / HEAPU8） 已被 Bench_MemoryView 的 ⑨ 证伪 —— .NET 不暴露裸堆入口；①-b 借任意一个 MemoryView 的 _unsafe_create_view().buffer，才是本工程唯一可靠的入口。此后逐一验证： ② pin 到的地址是否落在 buffer 内（不只是非零）、 ③ As() 的视图写入会不会回写到 C# 数组（零拷贝是否成立）、④ To() 副本的隔离性、 ⑤ 跨一次同步调用是否仍有效、⑥ 4 字节视图的对齐与宽度校验、 ⑦ 堆增长（memory.grow）会不会让 buffer detach、视图静默失效（本方案的硬伤）、 ⑧ 那块 buffer 是不是整块线性内存（跨数组验证）。进入本页会自动开始运行。
