JSON 解析 / 序列化（C# vs JS）

数据源：2config10.25341.1.json（约 7MB 的 modelInfo 三层配置， modelId → actionId → 记录）。起因：其他游戏的经验里，JSON 的序列化 / 反序列化是严重性能瓶颈—— 一份大配置反复 parse / stringify 会直接吃掉启动与热重载预算。这里把「C# 与 JS 解析同一份文件」的差距测成数字。

测什么

反序列化：C# JsonDocument.Parse（仅解析建只读 DOM）/ C# Deserialize<OriginMir2Config2>（解析 + 强类型映射）/ JS JSON.parse；
序列化：C# Serialize（强类型对象 / 只读 DOM 两档）/ JS JSON.stringify。

关键看两件事：① 纯解析 C# 与 JS 谁快；② 强类型映射 / 序列化比纯解析多花多少—— 后者正是「JSON 慢」的主因（慢不在解析，在映射成强类型对象）。
