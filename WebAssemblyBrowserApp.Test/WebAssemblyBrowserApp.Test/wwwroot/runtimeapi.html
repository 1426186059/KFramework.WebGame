运行时公开内存 API 探测

Bench_MemoryView 的 ⑨ 扫全局找 wasmMemory / HEAPU8 一无所获， 于是 Bench_HeapView 绕道去用 MemoryView._unsafe_create_view()（带 _unsafe 前缀，属内部方法）。 而 dotnet/runtime 源码里其实有一整套公开的内存 API：

export-api.ts 导出 localHeapViewU8() 系列与 setHeapU8/getHeapU8 系列； exports.ts 把 Module 连同这套 API 一起挂在 create() 的返回值上， 并另留了全局入口 globalThis.getDotnetRuntime(runtimeId)。 换句话说，⑨ 不是「没有入口」，而是候选名单没扫到它。

本页逐条实测：①-a 全局 getDotnetRuntime、①-b main.js 注入的 RuntimeAPI（主路）、 ①-c 老办法扫全局（同页对照）、② localHeapViewU8() 本身（含 buffer 是否为 SharedArrayBuffer）、 ③ 九个 localHeapViewXxx()、④ api.Module 上的 HEAPU8 与 wasmMemory、 ⑤ 三条来路的 buffer 是否同一块、⑥ 用公开 API 直写 C# 钉住的数组（不需要引子）、 ⑦ setHeapU8/getHeapU8 单值读写、⑧ 借 wasmMemory 精确观测堆增长。 凡涉及写入的，判据都是 C# 回读自己的数组。进入本页会自动开始运行。
